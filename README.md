# ชุมนุมพิทักษ์รักษ์รังสิต — ระบบจัดการของบริจาค

เว็บไซต์ของชุมนุมพิทักษ์รักษ์รังสิต (ร.ร.สวนกุหลาบวิทยาลัย รังสิต) สำหรับรับของบริจาค คัดแยก ขาย และบริจาคต่อ

- **ฝั่งสาธารณะ (ไม่ต้องล็อกอิน)** — 3 หน้า: หน้าแรก (เกี่ยวกับชุมนุม + รอบรับบริจาคปัจจุบัน), ไทม์ไลน์ (สิ่งที่ทำไปแล้ว คลิกดูรายละเอียดได้), ขายของ (สินค้าที่เปิดขาย + ฟอร์มจองซื้อ)
- **ฝั่งเจ้าหน้าที่ (ล็อกอินด้วยรหัสผ่านที่ใช้ร่วมกัน — ไม่ต้องมีบัญชี Google พิเศษหรือ Client ID ใดๆ)** — เพิ่ม 2 หน้าในเมนู: สต็อกของบริจาค, การเงิน
- เมนูทั้งหมดอยู่ในปุ่มสามขีด (☰) ถัดจากปุ่มสลับภาษา ปุ่มเข้าสู่ระบบ/ออกจากระบบอยู่ล่างสุดของเมนู

ข้อมูลทั้งหมดเก็บใน **Google Sheet** อ่าน-เขียนผ่าน **Google Apps Script** ที่ deploy เป็น Web App — ไม่มีขั้นตอนไหนต้องเข้า Google Cloud Console เลย

## โครงสร้างไฟล์
```
index.html             หน้าแรก: เกี่ยวกับชุมนุม + รอบรับบริจาค (เพิ่ม/แก้ไขได้เมื่อล็อกอิน) + ไทม์ไลน์ล่าสุด
timeline.html          ไทม์ไลน์เต็ม (สาธารณะ, คลิกแต่ละแถวดูรายละเอียด)
shopping.html          หน้าขายของ (สาธารณะ)
stock.html             สต็อกของบริจาค (ต้องล็อกอิน)
finance.html           การเงิน 3 ส่วน: อนุมัติคำสั่งซื้อ / รายได้อื่น / บริจาคเงินหลังขาย (ต้องล็อกอิน)
login.html             ล็อกอินเจ้าหน้าที่ (รหัสผ่านที่ใช้ร่วมกัน)
assets/css/style.css   สไตล์ทั้งเว็บ
assets/js/i18n.js      คำแปลไทย/อังกฤษ + สลับภาษา
assets/js/api.js       เรียก Apps Script + จัดการ session ล็อกอิน + อัปโหลดรูป
assets/js/app.js       ส่วนหัว (เมนูสามขีด) + ส่วนท้าย + การ์ด/ชั้นหนังสือที่ใช้ร่วมกัน
apps-script/Code.gs    โค้ด backend (วางใน Google Apps Script)
apps-script/README.md  วิธีตั้งค่า Google Sheet + Apps Script แบบละเอียด
```

## ขั้นตอนติดตั้งโดยสรุป (7 ขั้น)
1. สร้าง Google Sheet เปล่าๆ
2. เปิด Apps Script (Extensions > Apps Script) แล้ววางโค้ดจาก `apps-script/Code.gs`
3. ตั้ง Script property ชื่อ `ADMIN_PASSWORD` เป็นรหัสผ่านที่จะให้เจ้าหน้าที่ใช้ร่วมกัน
4. Deploy เป็น Web App (Execute as: Me, Who has access: Anyone) → คัดลอก Web App URL
5. เอา URL ที่ได้ไปวางใน `assets/js/api.js` (ตัวแปร `SCRIPT_URL`)
6. Push โค้ดทั้งหมดขึ้น GitHub แล้วเปิด GitHub Pages ตามขั้นตอนด้านล่าง
7. เปิดเว็บ ล็อกอินด้วยรหัสผ่านที่ตั้งไว้ ทดสอบใช้งาน

รายละเอียดทุกขั้นตอนดูได้ที่ `apps-script/README.md`

## Deploy ด้วย GitHub Pages
1. สร้าง repository ใหม่บน GitHub (public)
2. ใน terminal ที่โฟลเดอร์นี้:
   ```bash
   git init
   git add .
   git commit -m "พิทักษ์รักษ์รังสิต — initial site"
   git branch -M main
   git remote add origin https://github.com/<username>/<repo-name>.git
   git push -u origin main
   ```
3. ใน GitHub: ไปที่ repo > **Settings > Pages**
4. ที่ **Source** เลือก branch `main` โฟลเดอร์ `/ (root)` แล้วกด **Save**
5. รอ 1-2 นาที เว็บจะขึ้นที่ `https://<username>.github.io/<repo-name>/`

## ข้อมูลตัวอย่างที่ควรใส่ให้เว็บเมื่อเชื่อมต่อ backend แล้ว
ล็อกอินแล้วกด "+ เพิ่มรอบรับบริจาคใหม่" ในหน้าแรก เพื่อใส่ข้อมูลจริง เช่น:
- รับบริจาค: หนังสือทุกชนิด
- ช่วงวันที่: 24 มิถุนายน 2569 – 24 กรกฎาคม 2569
- บริจาคได้ที่: ร.ร.สวนกุหลาบวิทยาลัย รังสิต ตึก 1 ชั้น 2, 4, 8

## หมายเหตุสำคัญ
- ไม่ต้องเข้า Google Cloud Console หรือสร้าง Client ID ใดๆ เลย — ทั้งระบบใช้แค่บัญชี Google ปกติ (Sheet + Apps Script + Drive)
- เจ้าหน้าที่ทุกคนล็อกอินด้วย**รหัสผ่านเดียวที่ใช้ร่วมกัน** (ตั้งใน Script property `ADMIN_PASSWORD`) — ระบบจะไม่แยกว่าใครเป็นคนทำรายการไหน เหมาะกับชุมนุมขนาดเล็กที่ไว้ใจกันอยู่แล้ว ถ้ารหัสผ่านหลุด เปลี่ยนได้ทันทีที่ Script property
- ถ้ายังไม่ได้ใส่ `SCRIPT_URL` เว็บจะแสดงข้อความแจ้งว่ายังไม่ได้เชื่อมต่อ (ใช้ทดสอบหน้าตาเว็บได้โดยไม่ต้องรอ backend)
- ทุกครั้งที่แก้ `Code.gs` ต้อง deploy เวอร์ชันใหม่ (ดูหมายเหตุท้าย apps-script/README.md)
- เว็บนี้ออกแบบให้ใช้กับของบริจาคได้หลายประเภท ไม่ใช่แค่หนังสือ — ช่อง "ประเภท" และ "รับบริจาคอะไร" ในสต็อก/รอบรับบริจาคใส่เป็นข้อความอิสระได้
- อัปโหลดรูปได้ตรงจากมือถือ/คอมพิวเตอร์ทั้งฝั่งสต็อกและสลิปลูกค้า (เก็บใน Google Drive อัตโนมัติ) — ไม่ต้องหา URL รูปเอง
- ระบบกันการจองซ้ำ: ตอนลูกค้ากดสั่งซื้อ ของจะถูก "จอง" ทันที คนอื่นจะไม่เห็นเป็นของว่างอีก ถ้าแอดมินปฏิเสธ/ลบคำสั่งซื้อ ของจะถูกปล่อยคืนอัตโนมัติ
- สต็อก/คำสั่งซื้อ/รายการการเงิน แก้ไขหรือลบได้จากหน้าเว็บโดยตรง ไม่ต้องเข้าไปแก้ใน Google Sheet เอง (ลบสต็อกที่มีประวัติขาย/บริจาคแล้วจะทำไม่ได้ เพื่อกันข้อมูลบัญชีเพี้ยน)
- เซสชันล็อกอินจะหมดอายุอัตโนมัติใน 30 วัน (ตั้งได้ในโค้ด `SESSION_MAX_AGE_MS`)

## สิ่งที่ยังไม่ได้ทำ (รู้ไว้ก่อนใช้งานจริง)
ระบบนี้ครอบคลุมการใช้งานหลักครบแล้ว แต่ยังมีจุดที่ควรรู้ไว้สำหรับการใช้งานจริงในวงกว้าง:
- **การแจ้งเตือน**: ยังไม่มีอีเมล/LINE แจ้งแอดมินเวลามีคำสั่งซื้อใหม่ หรือแจ้งลูกค้าเวลาคำสั่งซื้อถูกอนุมัติ/ปฏิเสธ ต้องเข้ามาเช็คหน้าการเงินเอง
- **ไม่แยกตัวตนเจ้าหน้าที่**: เพราะใช้รหัสผ่านร่วมกัน จึงไม่รู้ว่าใครทำรายการไหน (แลกกับความง่ายในการตั้งค่า)
- **ไม่มีระบบผู้ใช้หลายระดับ**: ทุกคนที่รู้รหัสผ่านมีสิทธิ์เท่ากันหมด (แก้/ลบได้ทุกอย่าง) ยังไม่แยกสิทธิ์เช่น "ดูอย่างเดียว" หรือ "อนุมัติการเงินเท่านั้น"
- **รองรับผู้ใช้พร้อมกันจำนวนมาก**: เหมาะกับสเกลชุมนุม/สเกลเล็ก-กลาง (หลักร้อยรายการ) เพราะ Google Sheet + Apps Script มีข้อจำกัดด้านความเร็วเมื่อข้อมูลเยอะมากหรือมีคนใช้พร้อมกันเยอะมาก
- ถ้าอยากให้ทำเพิ่มข้อไหนในนี้ บอกได้เลย
